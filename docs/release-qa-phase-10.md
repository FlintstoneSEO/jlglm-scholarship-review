### Fixed: login redirect accepts browser-interpreted external form

- **Severity:** high
- **Element or file:** `src/routes/login.tsx`, `src/lib/auth-lifecycle.ts`
- **Viewport, route, or state:** `/login?next=...` after sign-in or with an existing session
- **Observed problem:** a value beginning `/\\` passed the old prefix check even though URL parsing can treat it as a different origin.
- **Evidence:** old guard checked only leading `/` and `//`; new unit test rejects `/\\evil.example` and `//evil.example`.
- **Exact recommended change:** resolve candidate against a fixed portal origin and accept only matching-origin paths.
- **Reason:** keep post-login navigation inside the portal.
- **Expected outcome:** external redirect forms fall back to `/`.
- **Verification method:** unit test and local production build pass; deployed redirect smoke test remains pending.

### Fixed: mobile auth pages had no visible H1

- **Severity:** medium
- **Element or file:** `src/routes/login.tsx`, `src/components/AuthPageShell.tsx`
- **Viewport, route, or state:** mobile `/login`, `/accept-invite`, `/forgot-password`, and `/reset-password`
- **Observed problem:** the H1 was inside a desktop-only panel, while the visible form title was H2.
- **Evidence:** source uses `hidden md:flex` for the panel; production browser accessibility tree showed the portal H1 and form H2 at its default desktop width.
- **Exact recommended change:** render the visible form title as the sole H1 and style the portal name as text.
- **Reason:** each auth page needs a descriptive first heading at all widths.
- **Expected outcome:** mobile and desktop both expose the page purpose as H1.
- **Verification method:** source test passes; rendered mobile retest remains pending after deployment.
